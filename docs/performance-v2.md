# 小待 Performance V2 · 单动作实验

这是独立角色实验，不替换 `index.html` 中的生产角色。基线：`main@3ecd975`；开发分支：`feat/performance-v2`。入口：`/character-lab/performance-v2.html`，或从原角色实验室进入。

## 静态造型先行

五张固定姿势 A–E 由 `js/xiaodai-performance-v2.js` 的 `POSES` 定义。它们不是把同一张 SVG 放大缩小：身体始终由十个同拓扑的轮廓点形成闭合贝塞尔路径，其中顶弧、肩部、左右侧、下腹与底弧分别移动；每条手臂有肩、肘、手的中心点与三段宽度。眼、眼皮、瞳孔、眉、嘴、便签、双脚和阴影都是独立参数。页面下方的五张卡片可以静止检查；点击卡片会显示在右侧大图。

| 姿势 | 剪影和情绪意图 |
| --- | --- |
| A Idle | 上窄下稳，手自然垂在两侧，眼神开放但克制。 |
| B Notice | 瞳孔先朝触碰方向，眼开大；一侧手轻抬，便签尚未完全跟上。 |
| C Anticipation | 顶弧下沉、下腹横向展开、手向内收；是局部轮廓重绘而非椭圆压缩。 |
| D Reaction | 顶弧升高、腰腹收窄、双手上扬，嘴形展开，脚稍离地。 |
| E Settle | 身体回落、双手不完全同步落下，便签反向回摆，喜悦留在表情里。 |

静态手机截图：`qa/performance-v2-pose-board-mobile.png`。原始路径与当前路径的可视化在“显示 V1 原始身体路径与 V2 轮廓点”开关中。

## 表演时间轴

`sample(t, timing)` 对身体、手臂、面部、便签、脚和阴影分别求值；`timing` 的 Notice、Anticipation、Reaction、Settle 四段毫秒数可在页面现场调整。默认共 1200ms。眼部先于身体到达 Notice；手臂与便签落后；收尾阶段保留约三分之一时间让各部件异步回位。单次动作可播放、暂停、慢放、拖到任意时间点和按约 1/60 秒步进。触碰比较舞台左右半区可选择触碰方向；右侧是正面表演的水平调度，不是伪三维转身。

左侧 V1 对照使用原 `XiaodaiRig` 和原 `XiaodaiMotion.ACTIONS` 的 `notice → tapReact → returnToIdle` 参数做**确定性重采样**，以支持与 V2 同步拖动。V1 的 78ms 淡出、120ms 淡入是按旧实现重现的；它不是在页面里同时触发两套不可寻址的实时点击事件。两个动作按总进度归一化，V1 原时长 2270ms，V2 默认 1200ms，因此并排比较的是节奏阶段和形态质量，而非相同毫秒时刻。

## 验证

在项目根目录运行：

```bash
npm run check
npm test
npm run test:performance
npm run test:browser
npm run test:server
```

`test:performance` 需要本机 Chrome，并通过本地 HTTP 服务验证 390px / 320px 视口、五个独立姿势、V2 节点持续存在、V1 固定路径、逐帧/拖动/播放/减少动态效果、调试视图和无浏览器异常。单元测试在 1200 个采样点检查轮廓、手和嘴的连续性。所有业务页面和通知仍由原文件运行；静态测试明确禁止在生产 `index.html` 加载 V2 模块。

本轮实测：`npm run check` 通过；`npm test` 27/27 通过；`npm run test:performance` 在 390px 和 320px 通过；原 `npm run test:browser` 的 60 秒 Idle、快速点击、任务 / Focus / Danger / Done、服务工作者与通知流程通过；`npm run test:server` 的订阅、排程、延迟推送测试通过。Chrome 的手机视口测试不能代替 iPhone 真机美术验收。

## 尚未解决的美术与技术限制

- 这是一个正面、单动作表演原型；没有新增侧面和背面运动时间轴，也没有把 V2 替换进 Now 或其他业务页面。
- 前手从身体两侧进入时，肩部遮挡在极端内收姿势仍略显硬；若要达到更高质量，应为前臂与手套分别设计遮挡层，而非继续增加形变点数量。
- 嘴型是同一闭合贝塞尔拓扑的连续变化，但舌头、齿列等复杂内部形态没有制作；惊讶到开心的过渡仍有进一步表演空间。
- 默认 1200ms 节奏已在桌面 Chrome 手机视口检查，真实 iPhone Safari 的触控延迟、帧间隔与主观手感仍需实机评估。
- V1 对照是可寻址采样，不能完全重现旧引擎在连续乱点或后台切换时的异步竞态；生产 App 的旧引擎回归由原浏览器测试单独负责。
