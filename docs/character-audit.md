# Xiaodai 角色系统审查（阶段 A）

基准：`main` 提交 `5a0b2a6`，即当前 GitHub Pages 上的 V5.4 PWA。该版本由用户上传的 V5.3 ZIP 演进而来。五张 `assets/dodo_*@2x.png` 是当前 App 正在使用的 1024×1024 角色素材。旧单文件 V5.6 SVG 尝试保存在 `backup/v56-before-v54-pwa`，仅供核对历史；当前 V5.4 另存于 `backup/v54-before-svg-rig`。角色改造在 `feat/xiaodai-svg-rig` 独立工作区进行。

## 当前静态造型的问题

1. 五张 PNG 分别画了整个人物，手、脚、便签、脸部位置没有共享坐标。Calm 坐着看书，Notice 举手，Urgent 抱钟，Danger 持强调物，Done 张臂跳起；直接切图时轮廓和重心突变。
2. 不同状态里的便签大小、倾角与面部比例不完全一致，缩到 54px 的 Today 图标后很难确认是同一个骨架。
3. 现有素材使用明显的高光、体积渐变和投影。它们适合做参考母版，但作为可变形 Rig 会呈现塑料玩具感，且高光随身体整体旋转会暴露平面图片属性。
4. Danger 图左下的棕色强调物从身体边缘伸出，远看可能被误认为尾巴。新侧面与背面不沿用这类突出物。
5. 当前没有左/右三分之四、侧面和背面的正式规则；任何“转身”都无法检查手脚连接和无尾巴设定。

## 当前动画的问题

1. `js/character-engine.js` 主要对包含整张 PNG 的 `.dodoPose` 做位移、旋转、缩放；手、脚、便签和原始瞳孔无法分别跟随或反应。
2. “眼神”只移动叠在图片上的白色高光，图片里的黑色瞳孔仍固定。白色眨眼遮罩也依赖近似坐标，在五张图上不可能始终贴合。
3. 面部叠层位于身体容器之外。主体动作时它不共享同一父坐标，容易出现脸与身体的相对漂移。
4. Idle 选择呼吸的权重达 60%，幅度约 0.8%，观察几秒时多数动作几乎不可察；跳跃和提示又与这些微动作缺少连续的预备和收尾。
5. 快速点击会频繁取消并从头启动动作，最终常只看到最后一次抗议，缺少从“注意到触摸”到“回应”的清楚表演。
6. 状态预览按钮只切换图片。Notice、Urgent 等状态没有一致的进入姿势；同样的动作也无法按情绪调整眼、嘴、手与便签。

## 集成边界与验收基准

- 业务 STATE 由 `js/urgency-engine.js` 计算，角色点击不得改变它。
- Now、Today、Focus、Settings、Danger、Done、模拟灵动岛、任务存储、Service Worker 与通知接口都已经存在。重构只替换角色绘制和动画接入。
- 当前基准 `npm test` 为 16/16，`npm run check` 通过；后续需继续验证真实页面与手机视口。
- 先让标准正面、三分之四和背面静态轮廓成立，再制作动作。大幅转身需要额外姿态，不使用水平压缩冒充旋转。
